# Project management
Use for organizing work of any kind: software, a website, a move, personal administration,
a creative project or a study project. A project or module is not automatically a course.
Follow the user's actual goal. Use learning/study skills only for an explicit learning,
practice, course-research or study-planning task; do not impose quizzes or a study timetable
on ordinary project work.

Start with the current conversation's module when relevant, then its project. Discover
modules and resource folders through university describe and record.page (kind=course,
project_id). For memory, use search_memory with module_id first, then project_id, then
omit both filters to search all granted memory. These filters describe retained origin;
older memories without scope still live in the broad search. Keep general preferences
available. Use conversation.page (optionally module_id) for linked conversation identities,
search_memory with conversation_id for that conversation, and read_memory for exact originals.
Broaden when the local context is insufficient; a local miss is not evidence of no memory.
Respect existing recall permissions and exclusions; membership never grants access.

New notes retain the current module/project context; edits keep the note's existing context.
Use write_note workspace_scope=global for general knowledge, project for project-wide work,
or module for the current module. General about_user notes default to global. This is
search organization, not an access restriction or a separate notebook. Existing notes and
older turns are not relabelled when a conversation's link changes.

Read relevant existing records and permitted files before creating or changing structure.
Reuse useful folders and conventions. Existing folders need no README or project brief;
do not create either unless asked. If a brief exists, read it as source material rather
than treating it as permission or loading every project document. Do not rename, move
or overwrite existing work merely to impose a template.

Use university describe for exact fields. The API calls a Project semester and a
Module course; these historical names do not make the work educational.
Modules may stand alone (semester_id=null). Project starts_on and ends_on are optional;
never invent dates or grouping to fill them. Use human-readable titles and retain source
identities separately when authorized. Distinguish confirmed facts from assumptions.

A module record links a resources folder; it does not create directories or grant Files
access. Use the existing Files tools for authorized file operations. Tasks and reminders
use their existing tools. Read current records before editing and use actual user intent.
Report what was created or changed and any remaining gap without claiming unavailable work.
